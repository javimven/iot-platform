- 2026-07-30: **bug crítico real encontrado en vivo: `GET /audit-log` y `GET /platform/audit-log` llevaban rotos desde siempre.** `AuditLogEntry.id` es `BigInt` en Postgres/Prisma, y `JSON.stringify` no sabe serializar `BigInt` de forma nativa — en cuanto había al menos una fila (que hay siempre, casi cualquier escritura registra auditoría), el endpoint respondía 500 ("Do not know how to serialize a BigInt"). Nunca se había detectado porque no existe ningún test para `AuditController`/`AuditService`, y nadie había llamado a este endpoint de verdad hasta construir el visor de auditoría en Flutter esta sesión. Corregido con un parche global (`main.ts`): `BigInt.prototype.toJSON` devuelve el valor como string — afecta a los tres procesos (api/ingestion/worker) por si aparece otro campo `BigInt` en el futuro, no solo a este caso. `id` pasa a viajar como string en la API (`OPENAPI.yaml` actualizado; un número de 64 bits no cabe con precisión en un `number` de JS/JSON de todos modos). Verificado en vivo contra el backend real: ambos endpoints devuelven ahora las entradas reales acumuladas durante esta sesión (invitaciones, cambios de rol, alta de organización...) en vez de 500.
